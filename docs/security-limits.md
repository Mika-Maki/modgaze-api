# 安全修复与按组限流

## 8787 与 Tunnel

保留 HTTP `8787`、监听地址和 Tunnel 回源方式；不改 HTTPS/管理端口绑定，也不改 Cloudflare 配置。外部 TLS 仍由 Tunnel/代理提供。更新服务进程会短暂断开连接，管理会话需重新登录。

## 分组并发 / RPM

在「上游分组 → 分组详情 → 分组 API 限流」设置，也可新建/编辑分组时填写。

```json
{
  "id": "provider-a",
  "rateLimits": { "maxConcurrent": 8, "rpm": 120 }
}
```

- 同组所有直通 Key、虚拟 Key **共享**额度；不同组独立。不是每个 Key 各获得一份配额。
- `0` = **无上限**，省略默认也是0；两个值都必须是0到100000的整数。
- 并发从认证后占用，到响应完成/中断才释放，包含完整SSE生命周期。RPM为精确滚动60秒内已获准的请求数，包括模型发现和后续400/404。限流拒绝不消耗配额。
- 超限返回HTTP429和整数秒 `Retry-After`，不会调用上游。
- 保存热生效，不重建计数器；由无上限启用RPM时从启用后的请求开始计数；有限→无限→有限不会抹掉尚有效的历史有限窗口。进程重启会清空内存计数。
- 可选全局 `rateLimits.api` 兼容总并发/RPM和每key限额，但默认四项均0，不对分组叠加隐藏的默认限额。

## WebUI / 管理保护

「系统与维护 → 系统设置 → WebUI / 管理限流」单独配置管理预算。HTTP/TLS管理入口共享预算，API8787不使用管理配额。

| 配置 | 默认 | 说明 |
|---|---:|---|
| admin.maxConcurrent | 64 | 管理全部在途请求 |
| admin.rpm | 600 | 管理全局RPM |
| admin.perIpMaxConcurrent | 32 | 每个真实socket来源并发 |
| admin.perIpRpm | 300 | 每来源RPM |
| admin.loginMaxConcurrent | 2 | 全局同时执行的密码KDF |
| admin.loginRpm | 10 | 每来源登录/密码操作RPM |

以上每项均支持0无上限。来源不信任X-Forwarded-For，避免伪造绕过；代理后的用户可能共享同一来源预算。静态资源也计管理配额；默认已覆盖30个首屏资源并发回归。healthz豁免。

错误登录不再触发所有来源共用的指数锁定；KDF先取得并发槽，完成后再释放，客户端断开不会提前释放仍在工作的KDF。WebUI轮询遇429按Retry-After退避，不自动重试写操作。

如果把管理限额设得太低，可在本地直接修改**运行时实际使用的配置文件**（本机为config/locall.json），保留0600权限；管理会重新读取限额以恢复，勿误改config/local.json。

## 其他修复与兼容变化

- Responses生命周期、previous_response_id按调用key/组/模型路由与有效上游凭据绑定；不同key即使同组也不能互读。只允许本进程见过并记账的response；未知、重启前、过期或被淘汰对象返回404，不回退到共享账号直接读取。缓存上限10000、TTL1小时，**不持久化**。如业务需要长期对象检索，应实现持久化所有权账本，而不是放开未知ID。
- 未建立归属映射的conversation/item_reference请求拒绝；客户端上游项目/组织header不再透传，可由管理员在route.project/organization固定。Idempotency-Key按调用者命名空间化。
- 所有已验证POST JSON规范化后转发，防止重复字段在本地与上游解析不同；保留字段语义而不保证原始空白、字段字面数字或重复字段。
- 明确配置的正整数model.maxOutputTokens成为硬上限；null/未设置仍为不设该硬上限。默认不任意加隐藏模型输出限制。
- `maxResponseBytes`默认256MiB，作用于解压后的响应累计字节，可在系统设置调整；不是RPM/并发，不能填0。超限后如响应头已发出则中断流，日志记录失败，不伪造一个已无法发送的HTTP错误码。
- 修复路由级env凭据测试脱敏、Unicode/跨chunk凭据去敏、CSRF字节长度异常、静态资源/配置备份符号链接越界；日志不返回原始管理异常。去敏不等于对恶意上游任意编码的绝对保密。
- finish/close终态只记录一次；客户端中断记499并释放并发。资源预算为进程内；多副本应接入共享限流/所有权存储。
