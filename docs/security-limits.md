# 安全修复与按组限流

## 8787 与 Tunnel

保留 HTTP `8787`、监听地址和 Tunnel 回源方式；不改 HTTPS/管理端口绑定，也不改 Cloudflare 配置。外部 TLS 仍由 Tunnel/代理提供。更新服务进程会短暂断开连接，管理会话需重新登录。

## 分组并发 / RPM

在「上游分组 → 分组详情 → 分组 API 限流」设置，也可新建/编辑分组时填写。

```json
{
  "id": "provider-a",
  "rateLimits": { "maxConcurrent": 8, "rpm": 120 }
}
```

- 同组所有直通 Key、虚拟 Key **共享**额度；不同组独立。不是每个 Key 各获得一份配额。
- `0` = **无上限**，省略默认也是0；两个值都必须是0到100000的整数。
- 并发从认证后占用，到响应完成/中断才释放，包含完整SSE生命周期。RPM为精确滚动60秒内已获准的请求数，包括模型发现和后续400/404。限流拒绝不消耗配额。
- 超限返回HTTP429和整数秒 `Retry-After`，不会调用上游。
- 保存热生效，不重建计数器；由无上限启用RPM时从启用后的请求开始计数；有限→无限→有限不会抹掉尚有效的历史有限窗口。进程重启会清空内存计数。
- 可选全局 `rateLimits.api` 兼容总并发/RPM和每key限额，但默认四项均0，不对分组叠加隐藏的默认限额。

## WebUI / 管理保护

「系统与维护 → 系统设置 → WebUI / 管理限流」单独配置管理预算。HTTP/TLS管理入口共享预算，API8787不使用管理配额。

| 配置 | 默认 | 说明 |
|---|---:|---|
| admin.maxConcurrent | 64 | 管理全部在途请求 |
| admin.rpm | 600 | 管理全局RPM |
| admin.perIpMaxConcurrent | 32 | 每个真实socket来源并发 |
| admin.perIpRpm | 300 | 每来源RPM |
| admin.loginMaxConcurrent | 2 | 全局同时执行的密码KDF |
| admin.loginRpm | 10 | 每来源登录/密码操作RPM |

以上每项均支持0无上限。来源不信任X-Forwarded-For，避免伪造绕过；代理后的用户可能共享同一来源预算。静态资源也计管理配额；默认已覆盖30个首屏资源并发回归。healthz豁免。

错误登录不再触发所有来源共用的指数锁定；KDF先取得并发槽，完成后再释放，客户端断开不会提前释放仍在工作的KDF。WebUI轮询遇429按Retry-After退避，不自动重试写操作。

如果把管理限额设得太低，可在本地直接修改**运行时实际使用的配置文件**（以启动参数或环境配置为准），保留0600权限。管理限额由独立默认5秒周期刷新，错误/读取失败保留最后一次有效限额；请求自身不再触发全量配置读取和编译，429也不会触发刷新。WebUI保存仍立即生效。恢复通常在下个刷新周期完成，而非要求先有一条被准入请求。

## 本机控制台与 Tunnel 判定

管理台把同时满足以下三条的请求视为「本机控制台」：

1. TCP 来源是 `127.0.0.1` 或 `::1`；
2. `Host` 是 `127.0.0.1`、`localhost` 或 `[::1]`（可带端口）；
3. 不带 `CF-Connecting-IP`、`CF-Ray`、`X-Forwarded-For`、`Forwarded`、`X-Real-IP` 任一转发身份头。

Cloudflare Tunnel 与同机反向代理都会让 TCP 来源看起来是回环，因此转发头一票否决；即使把 `adminAllowedHosts` 加上了公网域名，或把 Tunnel 的 Host 改写成 `127.0.0.1:8788`，也不算本机。

- **仅本机**：首次设置管理员密码、修改管理员密码、下载配置备份。Tunnel 会话调用这些接口返回 403。
- **Tunnel 可用**：登录后的常规管理（分组、模型、密钥、设置、导入、恢复、审计等）。进入后台仍需管理员密码登录；会话建立后不再逐次要求 Key/密码。
- **完整配置导出**：`GET` 只能取脱敏版本；原始配置必须 `POST` 并重新输入管理员密码，且与登录共享暴力破解预算。
- **备份下载**：无论本机还是 Tunnel 都只返回脱敏 JSON；下载接口本身还要求本机来源。

局限：如果同机代理刻意删除全部转发头并把 Host 改写成回环地址，它与真实控制台在 HTTP 层不可区分。不要把管理端口暴露到不可信网络；需要远程管理时，优先用 Tunnel 访问且接受上述判定。

## 其他修复与兼容变化

- Responses生命周期、previous_response_id按调用key/组/模型路由与有效上游凭据绑定；不同key即使同组也不能互读。只允许本进程见过并记账的response；未知、重启前、过期或被淘汰对象返回404，不回退到共享账号直接读取。缓存上限10000、TTL1小时，**不持久化**。如业务需要长期对象检索，应实现持久化所有权账本，而不是放开未知ID。
- 未建立归属映射的conversation/item_reference请求拒绝；客户端上游项目/组织header不再透传，可由管理员在route.project/organization固定。Idempotency-Key按调用者命名空间化。
- 所有已验证POST JSON规范化后转发，防止重复字段在本地与上游解析不同；保留字段语义而不保证原始空白、字段字面数字或重复字段。
- 明确配置的正整数model.maxOutputTokens成为硬上限；null/未设置仍为不设该硬上限。默认不任意加隐藏模型输出限制。
- `maxResponseBytes`默认256MiB，作用于解压后的响应累计字节，可在系统设置调整；不是RPM/并发，不能填0。超限后如响应头已发出则中断流，日志记录失败，不伪造一个已无法发送的HTTP错误码。
- 修复路由级env凭据测试脱敏、Unicode/跨chunk凭据去敏、CSRF字节长度异常、静态资源/配置备份符号链接越界；日志不返回原始管理异常。去敏不等于对恶意上游任意编码的绝对保密。
- finish/close终态只记录一次；客户端中断记499并释放并发。资源预算为进程内；多副本应接入共享限流/所有权存储。

## 资源引用默认拒绝

网关没有文件、向量库、容器或保存Prompt的所有权账本，因此不能把“知道ID”视为授权。以下协议语义槽在调用上游前返回403，错误类型为 `resource_reference_error`：Responses input_file/input_image 的file_id、Chat文件与音频ID、Anthropic文件source与container_upload、file_search的vector_store_ids、已有code_interpreter容器及auto容器file_ids、顶层容器和保存的prompt.id。相应query引用也拒绝；模型defaults合并后执行相同检查。此规则同时适用于直通Key和虚拟Key，没有共享凭据旁路开关。

内联file_data、base64媒体、文本、工具schema、function参数和metadata继续透传，不扫描普通用户JSON中的同名字段。Code Interpreter可使用显式 `{ "container": { "type": "auto" } }`，但不能指定已有容器或挂载未授权文件。已有Responses所有权检查不变。

兼容变化：此前使用供应商已上传资源ID的客户端现在会收到403，即使是同一个用户。需要该功能时应实现按调用Key且绑定上游项目/凭据的资源授权账本；不要移除检查后复用共享凭据。此修复不是通用第三方扩展协议验证器，新增资源型能力必须先实现授权。

监控：开启accessLog后，可按 `status=403 && outcome=resource_reference_error` 告警；request_id用于关联。默认不输出对象ID、正文、Key或其指纹，避免为了监控引入额外敏感信息。测试断言拒绝发生时上游调用数为0、日志不含提交的ID或密钥。

## 部署日志与脚本加固

启动入口使用私有umask，项目专属run目录收紧至0700，日志收紧至0600（包括旧文件）。拒绝不安全文件类型/符号链接/非本用户文件，再通过已校验文件描述符交给子进程；不收紧/run、/var/log等系统共享目录。路径和环境参数不再插值为shell程序，带空格和引号的值仍作为单个参数处理。

这些权限变更在使用新启动脚本时生效，不会自动修改正在运行的旧服务或既有线上日志。审计仍按显式开关写stdout；maxEntries仅限制内存。日志轮转与保留期见[请求审计文档](request-audit.md#日志保留与轮转)。
